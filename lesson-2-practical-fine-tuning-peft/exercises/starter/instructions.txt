Background
What is PEFT? Instead of fine-tuning all billion parameters of a language model, PEFT adds small "adapter" layers that train only 5-15% of parameters. This:

Reduces training time and memory requirements
Preserves the base model's general knowledge
Enables task-specific specialization
LoRA (Low-Rank Adaptation):

Adds small trainable matrices to attention layers
Key parameters: r (rank), alpha (scaling), dropout, target_modules

Return as a list that can be converted to a Dataset object

Step 3: Configure LoRA Parameters
High-level instruction: Complete the configure_lora() function to return a LoraConfig object

Details:

Set r (rank): Start with 8 (lower = more efficient, higher = more expressive)
Set lora_alpha: Typically 2x the rank (e.g., 16 if r=8)
Set lora_dropout: 0.1-0.15 for regularization
Set target_modules: Target attention layers ["q_proj", "v_proj"]
Set task_type: "CAUSAL_LM" for language modeling
Hints:

Higher rank = more parameters to train = potentially better performance but slower
Alpha controls the scaling of LoRA updates
Targeting more modules (q, k, v, o projections) = more parameters

High-level instruction: Complete the run_sft_training(config, train_examples) function

Details:

Load the base model specified in config.base_model_name
Load the corresponding tokenizer
Convert train_examples to a Dataset object
Create a LoraConfig using your configure_lora() function
Set up TrainingArguments:
output_dir: config.output_model_path
num_train_epochs: config.num_train_epochs
per_device_train_batch_size: config.per_device_train_batch_size
learning_rate: config.learning_rate

Initialize SFTTrainer with model, training args, dataset, and peft_config

Save the model using trainer.save_model()
Step 5: Implement Model Validation
High-level instruction: Complete the validate_model(model, tokenizer, val_examples) function

Details:

Take a few validation examples (patients not in training set)
For each example:
Format as a prompt: "Determine eligibility: [patient_summary]"
Use tokenizer.encode() to convert to token IDs
Use model.generate() to get the model's prediction
Decode the output with tokenizer.decode()
Check if prediction matches actual eligibility status
Calculate accuracy: (correct predictions / total predictions)

Common Pitfalls to Avoid
Configuration Errors:

Mismatched tokenizer and model
Incorrect target modules for LoRA (not all models use same layer names)
Batch size too large causing out-of-memory errors
Training Issues:

Learning rate too high (causing loss to explode)
Learning rate too low (no learning)
Not enough training data (less than 50 examples)
Overfitting (training for too many epochs on small dataset)
Data Formatting:

Inconsistent prompt formatting between training and inference
Not properly tokenizing the dataset
Including test data in training set
Debugging Tips
If training fails:

Out of Memory: Reduce per_device_train_batch_size to 1, increase gradient_accumulation_steps
Loss not decreasing: Check learning rate, verify data is properly formatted
Poor validation: Check if model is overfitting, try more training data or regularization
Slow training: Use GPU if available, reduce dataset size for initial testing

Good signs:

Training loss decreases smoothly
Validation accuracy improves over epochs
Model predictions match expected eligibility for clear-cut cases
Warning signs:

Loss fluctuates wildly → learning rate too high
Loss plateaus immediately → learning rate too low or data issue
Perfect training accuracy but poor validation → overfitting
